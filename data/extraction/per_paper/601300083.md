## Evidence writeup

**Clinical Domain:** ED triage-note text predicting hospital admission (Amiens-Picardy University Hospital, ~260K ED records). No ED-specific label exists → `EHR`.

**XAI Method/Scope:** LIME, applied per-instance (Figs. 1-2 show single-patient explanations) → `Local`.

**Study Design/Participants:** No systematic clinical-utility evaluation, two illustrative cases discussed qualitatively → `MethodPaper`. One physician co-author reviewed explanations → `N_Participants=1`, `Participant_Type=Clinician`.

**Evaluation Type:** No quantitative fidelity metric, no simulation task, no trust scale, no decision-quality comparison, no outcome measure — the informal two-example physician commentary meets no taxonomy minimum → `None` (flagged, see below).

**Realism/EV:** Real hospital data + informal, non-independent single-clinician face-validity review, no assigned task, no interface, no outcome measure. `Realism_Level=1` per the rubric's lower-level-when-ambiguous rule, against a genuine Level-2 alternative given clinician involvement.

**Clinician Involvement:** `Clinician_Eval=Yes`, `Clinician_Role=Rater`; `Clinician_Design=No` (no clinician input into system design described).

**Outcomes/Trust:** `Trust_Claim=Plausibility` — "aims to foster trust and confidence" with no calibration-under-varying-reliability evidence. `Trust_Only=No` (no trust questionnaire exists at all, so the "sole evaluation" condition doesn't apply).

**Quality/RoB:** See QR_Notes above; `QR_Faithfulness=1` matches the rubric's own "face validity, not formal verification" example.

**Method Justification:** `Computational` — model-agnosticism/transformer-compatibility is the only stated rationale for LIME.

**Framework Classification:** `VilonLongo_Category=HumanCentred_Qualitative` (open-ended physician commentary, no close-ended instrument) — cleanly coded. `DoshiVelez_Category` is the problem — see flags.

**Regulatory-Relevant Evidence:** All four `No` — no tested comprehension, no calibration test, no explicit uncertainty-transparency mechanism, no realistic-workflow evaluation.

## Flags for reviewer — includes a genuine schema gap

1. **`Zotero_Key`** — blank.
2. **`Eval_Type = None` vs. the informal clinician review** — the paper does have a physician looking at real explanations, but it fails every minimum requirement in `eval_type_taxonomy.md`. This creates a documented tension with `Realism_Level=1`/`EV_Participant=2`, which *do* register that involvement. Decide whether `None` is right or whether this is a taxonomy gap worth logging in `memos/decision_log.md`.
3. **`Realism_Level` boundary (1 vs. 2)** — genuinely ambiguous. Coded conservatively at 1; you may prefer 2 given the clinician involvement.
4. **`DoshiVelez_Category` schema conflict — the important one.** Coded `FunctionallyGrounded` as the closest available label, but this directly contradicts the schema README's own stated mapping rule that `FunctionallyGrounded` requires `N_Participants=0`. This paper has `N_Participants=1`. None of the three Doshi-Velez buckets cleanly fits "an eval coded `None` but with one informal, non-independent human reviewer." **If this pattern recurs across the other papers, it's worth a decision-log entry defining how to code `DoshiVelez_Category` when `Eval_Type=None` but a human was informally involved** (e.g., add a documented tie-break rule rather than resolving it silently paper-by-paper).
5. **Independence concern** — the sole evaluator is a paper co-author, not a recruited/blinded participant. Weakens `QR_Participant`, `Trust_Claim`, and `Outcome_Demonstrated` — flagged in the row itself, noting it here for visibility.
